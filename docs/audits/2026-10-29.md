# Audit de tailwind-canonical — 29 octobre 2026

## Conclusion

Le risque principal est la fidélité des transformations automatiques : plusieurs chemins pouvaient modifier du JavaScript, des chaînes sans rapport avec Tailwind ou des fichiers exclus. Ces défauts existaient malgré 802 tests initialement réussis. Les corrections de cet audit ajoutent des reproductions ciblées, des tests avec le véritable moteur ESLint et des contrôles du paquet compilé. L'architecture reste sans dépendance runtime obligatoire ; les intégrations ESLint et tailwind-merge demeurent optionnelles.

Ce document distingue les défauts démontrés et corrigés des limites qui demandent un travail supplémentaire. Il ne constitue pas une garantie de prise en charge de toute syntaxe JavaScript, Vue ou Svelte, ni de tous les thèmes Tailwind.

## Périmètre et méthode

- Lecture des modules `src/core`, `src/io`, CLI, plugin ESLint, configuration, documentation, manifeste et workflows.
- Trois analyses indépendantes : transformations pures ; CLI/découverte/I/O ; API/ESLint/documentation/distribution.
- Reproductions minimales des défauts, puis régressions ciblées et vérifications globales.
- Audit du lockfile via `pnpm audit` et consultation des trois avis de sécurité effectivement signalés.
- Compilation et extraction du tarball hors du dépôt, sans `node_modules` : imports API/plugin et lancement du CLI.
- Pas de publication npm, de push, de commit ni de lancement des workflows distants.

Versions résolues auditées : Node local 24.22.1 ; pnpm 11.4.0 ; TypeScript 7.0.2 ; Biome 2.5.15 ; tsx 4.23.15 ; knip 6.41.0 ; Lefthook 2.2.1 ; ESLint 10.9.1 ; tailwind-merge 3.7.0. La compatibilité déclarée Node commence à 22.6 et la CI conserve les branches Node 22 et 24. La matrice consommateurs ajoute les versions ESLint et tailwind-merge listées ci-dessous.

## Défauts corrigés

Les priorités décrivent l'impact avant correction. P1 : risque sur le code, les fichiers ou l'intégration CI ; P2 : résultat fonctionnel incorrect ; P3 : contrat ou maintenance.

| Priorité | Défaut et reproduction | Correction et preuve |
|---|---|---|
| P1 | `dedupeContent` sur ``cn(`p-4 ${a + a + a}`)`` supprimait un opérateur `+` et cassait l'expression. | `class-strings.ts` isole les expressions et fragments dynamiques ; `deduplicator.ts` protège aussi son API directe. Régressions templates. |
| P1 | `rounded-s-lg rounded-e-lg` perdait une des deux classes : les directions logiques étaient interprétées comme deux rayons globaux concurrents. | Les arrondis logiques ne passent plus dans le regroupement des coins physiques. Régressions s/e et coins logiques. |
| P1 | Le plugin visitait toutes les chaînes : `const message = "Hello  world"` pouvait perdre un espace ; une requête contenant `text-[12px]` pouvait devenir `text-xs`. | Détection AST limitée aux attributs de classes et appels reconnus ; vrais tests `Linter`, chaînes métier préservées. |
| P1 | Un token partiel ``text-[12px]${suffix}`` pouvait être remplacé comme s'il était entièrement statique. | Frontières d'interpolation préservées dans le CLI et ESLint ; seuls les tokens statiques complets sont candidats. |
| P1 | `process.exit()` arrêtait le CLI avant vidage de stdout : un rapport de 6 000 résultats était tronqué à 65 536 octets. | `process.exitCode` laisse stdout se vider. Régressions enfants pour JSON et SARIF volumineux. |
| P1 | Les exclusions glob utilisaient une autre grammaire que la découverte : `!**/[ab].tsx` ne protégeait pas les fichiers attendus. | `path.matchesGlob` remplace le convertisseur regex maison ; tests classes de caractères et extglobs. |
| P1 | Les liens de fichiers découverts dans un répertoire pouvaient conduire les corrections vers un fichier extérieur à la cible. | Découverte limitée aux fichiers réguliers, via parcours et glob ; test prouvant que la cible externe reste inchangée. Un lien explicitement nommé reste volontairement supporté et documenté. |
| P2 | Le plugin supprimait `leading-6` devant `text-[13px]`, alors que le CLI protégeait déjà cette combinaison. | Extraction d'un helper pur `mergeClasses`, partagé par CLI et plugin ; régressions comparant la préservation de l'interligne. |
| P2 | La recherche de motifs répétitifs réunissait toutes les classes du fichier : faux motifs entre éléments et motifs réels manqués si le reste du fichier différait. | Frontières conservées dans `FileClasses.classLists` ; fallback compatible pour l'API existante. Test avec trois fichiers différents, deux occurrences réelles par fichier. |
| P2 | `mt-[var(--space)]` et `mt-[calc(1rem-2px)]` étaient ignorés par l'analyse d'échelle, qui cherchait le dernier tiret dans la valeur. | Séparation propriété/valeur avant le crochet ; test des deux expressions arbitraires. |
| P2 | Les pseudo-couleurs `constructor` et `toString` pouvaient accéder aux propriétés héritées de l'objet de familles et rendre le rapport invalide. | Recherche limitée aux propriétés propres, avec test de ces noms. |
| P2 | Un dossier nommé `folder.tsx` pouvait être pris pour un fichier par glob puis provoquer `EISDIR`. | Filtrage des fichiers réguliers et régression. |
| P2 | Watch accepté avec JSON/SARIF produisait un flux texte incompatible avec le reporter demandé. | Refus explicite de la combinaison lorsque le watch est actif ; aide et documentation alignées. |
| P2 | Des appels imbriqués comme `cn(cn("p-[16px]"))` produisaient deux diagnostics pour la même occurrence. | Plages d'extraction dédupliquées. Tests de cohérence entre analyse et correction. |
| P2 | Le schéma ESLint refusait des champs valides de `Config` alors que la documentation promettait de réutiliser la configuration partagée. | Schéma complété et validation runtime partagée ; les deux règles prennent les contextes configurés. Champs influents et champs seulement acceptés explicités ; test avec configuration complète. |
| P2 | Les suppressions multilignes étaient respectées par les diagnostics mais les corrections utilisaient seulement la ligne de début de chaîne. | Transformations segmentées par lignes autorisées ; régressions attribut et template `cn`. |
| P2 | Des faux appels dans les commentaires ou dans des chaînes de prose pouvaient être reconnus comme des classes. | Plages lexicales protégées pour les commentaires et chaînes externes, y compris après `return` sans espace ; syntaxes ambiguës laissées intactes. |
| P1 | Le scanner CLI pouvait changer des prédicats, arguments de fonctions imbriquées et identifiants de variantes dans un appel utilitaire. | L’extraction reconnaît désormais les seules positions de classes des objets et options ; prédicats et identifiants restent intacts. Les expressions inconnues ne sont pas évaluées. |
| P2 | La règle de conflits devenait silencieusement inactive sans `tailwind-merge`. | Erreur explicite avec commande d’installation quand cette règle est activée ; la règle canonique et le preset recommandé restent utilisables sans ce peer. |
| P3 | Une surcharge `customTextTokens: {12: 'tiny'}` était signalée comme un token natif. | Le marqueur dépend du token réellement choisi, pas seulement de la taille en pixels. |
| P3 | Le remplacement d'attributs réécrivait `className = ...` même sans changement des classes. | Remplacement de la seule plage de contenu ; format périphérique conservé. |
| P3 | La documentation indiquait TypeScript 6 alors que le manifeste et le lockfile utilisaient TypeScript 7 ; elle annonçait trois détecteurs pour quatre lignes. | Instructions projet et README corrigés ; type du preset ESLint resserré pour être utilisable en configuration typée. |

## Dépendances et sécurité

Le lockfile contenait `brace-expansion@5.0.9`, amené par ESLint → minimatch, concerné par trois avis :

- [CVE-2026-102277 / GHSA-q2hr-2g5m-vwhr](https://github.com/advisories/GHSA-q2hr-2g5m-vwhr) : consommation CPU quadratique, gravité modérée, correction 5.0.12.
- [CVE-2026-102278 / GHSA-qhr7-859c-m2p7](https://github.com/advisories/GHSA-qhr7-859c-m2p7) : récursion non bornée, gravité haute, correction 5.0.11.
- [CVE-2026-102276 / GHSA-6j4f-fj2g-mc7p](https://github.com/advisories/GHSA-6j4f-fj2g-mc7p) : épuisement de pile dans le traitement des virgules, gravité haute, correction 5.0.10.

Le verrouillage ciblé dans `pnpm-workspace.yaml` et le lockfile impose maintenant 5.0.12. `pnpm audit --json` retourne zéro avis après correction. Cette contrainte protège le graphe de travail du dépôt ; elle ne force pas la version des dépendances d'ESLint chez les consommateurs du paquet.

Scénario conditionnel : une configuration de glob non fiable atteint le moteur vulnérable via les outils ESLint, provoque un calcul excessif ou un arrêt par épuisement de pile et interrompt l'analyse locale/CI. Les avis établissent la vulnérabilité du paquet installé ; cet audit n'a pas démontré un chemin d'exploitation distant dans tailwind-canonical. La bibliothèque ne déploie pas de serveur HTTP ; authentification, sessions, CORS et en-têtes HTTP ne sont donc pas des surfaces pertinentes ici. Aucun enchaînement d'attaque supplémentaire n'est établi.

## Suite corrective demandée après l’audit

Les six points actionnables du tableau initial ont été traités :

| Sujet | Résultat |
|---|---|
| Extraction des classes | Tokenizer équilibrant groupes, commentaires, chaînes et regex ; positions de classes reconnues dans les objets `cn`/`clsx`, les variantes et variantes composées `cva`. Prédicats, identifiants et `defaultVariants` préservés. Guillemets du texte JSX, attributs bracés avec espaces et templates imbriqués couverts par régressions. Un appel avec regex/division ne masque plus les suivants. |
| Surveillance | Nouveaux fichiers, globs initialement vides, suppression/recréation et exclusions pris en compte. Racines minimales, lots d’événements sérialisés, configuration principale rechargée (ESM et CommonJS). Configuration invalide : aucune écriture jusqu’à correction. Erreurs de backend signalées ; watchers, timers et listeners fermés sur arrêt. |
| Compatibilité | Artefact empaqueté installé dans des consommateurs temporaires : API, CLI, binaire installé, règles/preset ESLint et déclarations TypeScript strictes. Neuf combinaisons exécutées, dont les versions minimales ; installation sans peers également vérifiée. CI reproduit cette matrice. |
| Thème personnalisé | `useDefaultTheme: false` désactive toutes les équivalences inférées : seuls `customTextTokens` et `customSpacingTokens` explicitement configurés en pixels s’appliquent. Les rem ne sont pas convertis implicitement. Tests moteur, configuration, API fichiers et ESLint. |
| Contrat de pureté | Documentation corrigée : certaines fonctions sont pures, mais les réexports chargent Node. Le paquet cible explicitement Node et ne promet pas une entrée navigateur. Aucun changement d’architecture ni nouvelle cible navigateur introduits. |
| Performance | `pnpm benchmark` crée un corpus déterministe JSX/Vue/Svelte, vérifie les diagnostics attendus et l’idempotence, puis mesure découverte, analyse, pipeline et cohérence. Taille, environnement, médiane et p95 publiés ; aucun seuil de temps arbitraire en CI. |

ESLint **8.57.1, 9.0.0, 9.39.5, 10.0.0 et 10.13.0** ; tailwind-merge **2.0.0, 2.6.1, 3.0.0 et 3.7.0**. ### Limites intrinsèques explicites

- L’extraction n’évalue pas le JavaScript : propriétés calculées, spreads et appels non configurés restent dynamiques. Leur contenu n’est pas réécrit comme s’il était statique.
- La configuration principale est rechargée ; les helpers qu’elle importe gardent le cache normal de Node. Leur modification nécessite un redémarrage du watch.
- L’outil ne lit pas le thème Tailwind effectif : utiliser le mode explicite ci-dessus pour un thème personnalisé. Le regroupement statistique de styles reste un signal à examiner, pas une preuve d’erreur de design.
- Les benchmarks sont synthétiques, exécutés localement ; les performances sur d’autres projets et plateformes ne sont pas garanties. La CI distante n’a pas été déclenchée dans cette session.

## Vérification finale

- Socle initial : 802 tests réussis, aucune modification préexistante.
- Audit initial corrigé : **833 tests réussis**. Après la suite corrective : **856 tests réussis**, aucun échec ni test ignoré ; `pnpm typecheck`, `pnpm lint`, `pnpm knip` et `pnpm build` réussis.
- `pnpm audit --json` après mise à jour : zéro avis.
- Archive extraite hors du dépôt : imports API/plugin et CLI fonctionnels sans `node_modules` ; aucun test embarqué.
- `pnpm test:compat` final : neuf combinaisons réussies et installation sans peers vérifiée à partir de l’artefact final.
- `pnpm benchmark` et son passage d’arguments sont vérifiés ; les mesures du corpus complet sont consignées ci-dessus.
- Les workflows distants et la matrice Node 22/24 n'ont pas été exécutés localement. La validation locale utilise Node 24.22.1.
- Relecture indépendante des nouveaux chemins lexicaux et du plugin : les cinq reproductions finales de corruption ont été rejouées après correction et sont protégées. `git diff --check` réussit.

## Points solides à préserver

- Absence de dépendance obligatoire à Tailwind ou à un parseur volumineux ; peers optionnels.
- Séparation des transformations et de l'accès aux fichiers, utile aux tests et aux intégrations.
- Valeurs sans équivalent canonique laissées intactes, avec de nombreux tests de régression.
- Configuration validée, support explicite v3/v4, traitement des variantes et de l'importance.
- Permissions GitHub limitées par workflow et publication npm avec OIDC/provenance.
- Tests existants nombreux et rapides ; les régressions ajoutées exercent désormais aussi de vraies intégrations.
